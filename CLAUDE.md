# CLAUDE.md — Solascent website

Instructions for Claude Code when working on this repository. Read this first, then `NOTE.md` for status and open items.

## What this project is
A premium reed-diffuser storefront for the home-fragrance brand **Solascent**. A plain static site (HTML, CSS, vanilla JS). **No framework, no npm, no dependencies, no build step to deploy.** Hosted on Vercel from this repo (`main` branch). Repo: https://github.com/arqqadevelpment/sola-scent

## Golden rules
1. **Do exactly what is asked.** The owner iterates with short instructions plus a screenshot. Change only what was requested; if you notice something else, mention it in one line instead of changing it.
2. **Never invent facts.** Prices, sizes, longevity, contact details, legal text and customer reviews are placeholders until the owner supplies them. Placeholders use the `ph()` helper (dashed italic text). The six reviews on the home page are **dummy content for layout only**; say so if asked about launch.
3. **Product names:** the site uses **Ancient Amber, Mon Cherry, Apple Pine** (from the brand content PDF), with collections **Sacred Amber, The Secret Garden, Root & Ripe**. The bottle photos still show the old names (Dark Amber, Cherry Mongolia, Apple Cinnamon) until new photos exist. Do not mix the two sets of names in text. Flag a mismatch rather than silently "fixing" it.
4. **Never commit private or large source files.** `.gitignore` is a whitelist on purpose (see "Git"). Ask before pushing anything outward. Never add secrets or `.env` files.
5. **Say what you did not verify.** Prefer measuring in the browser (computed styles, sizes, line counts) to guessing, and state clearly what you could not check (for example mobile, or animation feel).

## How the code is organised
```
_build/build.py            Python 3 page generator (standard library only). Source of truth for page HTML.
solascent-website/         The deployable site (Vercel output directory)
  *.html                   GENERATED by build.py. Committed so the site deploys with no build step.
  css/styles.css           All styles, edited directly. Appended in sections (newest rules last, they win).
  js/main.js               Cart, mobile menu, reveal + parallax + word-split animations, forms, reviews toggle.
  js/config.js             Store settings: prices, checkout URL, form endpoints. PUBLIC values only.
  assets/img/              Optimised images used by the pages (see "Images").
vercel.json                Static deploy config (no framework/build, output dir solascent-website).
```

### Workflow for any page change
1. Edit **`_build/build.py`** (HTML/copy/structure) and/or **`css/styles.css`**, **`js/main.js`**, **`js/config.js`** directly.
2. **Never hand-edit the generated `*.html`** — the next run of the generator overwrites it.
3. Regenerate: `python3 _build/build.py` (Python 3.9+ works; avoid backslashes inside f-string expressions, which break on 3.9/3.10).
4. Preview: `cd solascent-website && python3 -m http.server 8000` → http://localhost:8000
5. The generator stamps CSS/JS/images with `?v=<hash>` so browsers pick up changes. After CSS edits you must regenerate so the hash changes; if something looks stale, hard-refresh (Cmd/Ctrl+Shift+R).
6. Regenerating should change only the pages you meant to; check `git status` and `git diff --stat`.

## Design system (follow it)
**Palette** (Brand Design System): Obsidian `#0B0B0A`, Matte White `#FFFCF3`, Solar Brass `#D2AC2B` (accent/CTA), Carbon Brown `#241F1A`, Raw Concrete `#9A9892`. Rule: ~75% Obsidian/Matte White, ~15% brass, ~10% support.
**Theme classes** (CSS variables `--bg --fg --ac --acfg --surf --plinth --line`): `t-dark`, `t-light`, `t-cherry`, `t-apple`. Put the class on a section to theme it.
**Type:** brand fonts are *thmanyah serif display* (headings) and *Aktiv Grotesk* (body/UI) — not yet installed. Stand-ins: Cormorant Garamond (`--serif`), Hanken Grotesk (`--sans`), DM Mono (`--mono`, small uppercase eyebrows). When the brand font files arrive, add `@font-face` and swap the variables in `:root`; remove the Google Fonts link in `build.py`.
**Buttons:** always full pill (`border-radius:999px`, class `.btn`). Gold on dark sections, black on light sections. Secondary: `.btn.ol` (outline), small: `.btn.sm`.
**Eyebrows:** small mono uppercase labels, numbered on the home page (`02 — Brand story`).
**Headlines:** serif, restrained sizes (the owner repeatedly asked to reduce sizes). Hero, collections intro, signature and closing headlines are **single line / fixed two lines** using `white-space:nowrap` spans (`.ln`). Keep them from wrapping at 375px as well.
**Spacing/feel:** generous padding, quiet luxury, product-led. Avoid decoration that competes with the product.
**Header:** centred full logo lockup (`logo-lockup-light.png`); left = Ancient Amber, Mon Cherry, Apple Pine; right = About Us, Shop, Contact Us, cart **icon** with count badge. Mobile (<1180px): Menu left, logo centre, cart right; full-screen menu lists all seven links. On the home page the header floats transparently over the hero and turns solid after scrolling (`.home .site-header.stuck`).
**Footer:** newsletter block, Shop / Support / Social columns (all items identical sans style), legal links (Privacy Policy, Store Policy), Visa + Mastercard logos.

## Motion conventions (in `main.js` + CSS)
- Scroll reveal: elements get `.rv`, then `.in` via IntersectionObserver. Do **not** put `.rv` on layers that use `transform` for parallax (`.pbg`, `.cbg` are skipped).
- Parallax: add `data-parallax` on a section, a `.pbg` layer (image, `top:-18%; height:136%`) and optionally `.pcon` text layer.
- Word reveal: `data-split` on a heading inside a `.story-band`.
- Always respect `prefers-reduced-motion` (already handled; keep it that way).

## Cart, forms and config
Cart state is in `localStorage` (`solascent-cart-v1`). Prices come from `js/config.js` (`price: null` → "Price TBC"). **Checkout is not connected**: set `checkoutUrl`. Contact form and newsletter run in **demo mode** (send nothing) until `formEndpoint` / `newsletterEndpoint` are set. Everything in `config.js` is public; real payments need a hosted checkout or a backend.

## Git and deployment
- Branch: `main`. Commit messages: short imperative subject + body explaining why.
- `.gitignore` is a **whitelist**: only `solascent-website/`, `_build/`, `vercel.json`, `README.md`, `NOTE.md`, `CLAUDE.md` are tracked. Loose files in `solascent-website/assets/` (large PNGs, internal PDFs) are intentionally ignored; the repo is **public**.
- Never commit `node_modules`, `dist`, `build`, `.next`, `.env*`, keys or brand PDFs.
- Vercel: framework none, no install/build command, output directory `solascent-website` (all in `vercel.json`). **No environment variables are required.**
- Before pushing: `git status`, review the diff, regenerate pages, load the site locally.

## Communication style with the owner
Concise. State what changed, what was checked, what was not. Offer one clear next step. Do not paste long code back. Flag conflicts (names, content, missing assets) before acting on them.
